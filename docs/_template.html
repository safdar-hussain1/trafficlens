TrafficLens turns any video feed — a traffic camera, an RTSP stream, a webcam — into live counts and calibrated speeds. Draw a gate on the video, click four points to calibrate, and every crossing is logged with class, direction and km/h.

What it does

A traffic camera brain, not a demo script

Count anything

Any COCO class — cars, trucks, buses, bikes, people. Pick classes per session; gates tally by class and direction.

Real speeds

A four-point road-plane homography maps pixels to metres. Speeds are measured in the world, not in pixels — and stay honest until you calibrate.

Any source

Video files, webcams, RTSP/HTTP streams. The same YAML config drives the CLI and the web app.

Draw, don't code

Gates are drawn on the live video and moved while the session runs. Calibration is four clicks and two numbers.

Violations

Set a speed limit and every over-limit crossing is flagged and photographed into a snapshot gallery.

Exports

Events CSV, summary JSON, and a replay file that powers this page. Every count is auditable down to the frame.

The core idea

Counting that physically can't skip

Most tutorials count a vehicle when its centre point falls inside a thin band around the line. That breaks both ways: fast objects jump the band between frames, and objects that graze the band without crossing get counted anyway. TrafficLens instead tests whether the movement segment between two frames intersects the gate — geometry that works at any speed. Race the two rules yourself:

0segment gate
0±8 px band

Speed methodology

Pixels are not metres

The calibration

German autobahn lane dashes repeat every 18 m (6 m paint, 12 m gap). Five dash starts along the A40's lane divider plus the parallel lane edge give ten image↔world correspondences; a least-squares homography maps the whole road plane to metres.

  • Probe rows step 18.0 m ± 0.4 m through the calibrated corridor.
  • A mid-corridor car footprint measures 4.96 m — real cars are 4.5–5 m.
  • Speeds resolve the queue: ≈15 km/h far field → ≈60 km/h at the bridge.

Verified by synthetic cameras

The estimator is tested against tracks projected through a known synthetic camera, where ground truth is exact:

✓ recovers 72.0 km/h ground truth within 3%

✓ stays within 10% under 1.5 px detector jitter

✓ parked objects report no speed (jitter ≠ movement)

✓ unit conversion km/h ↔ mph exact

tests cover the geometry, calibration maths, config validation, API contract, and the band counter's failure modes.

The app

A control room in your browser

`trafficlens serve` opens the operator console: pick a source, draw gates on the live stream, calibrate with four clicks, watch counts and speeds land in real time — violations get photographed automatically.

Or stay in the terminal

# install & fetch CC-licensed sample footage
pip install -e . && trafficlens fetch-samples

# full analysis of the motorway clip: counts, speeds, violations, exports
trafficlens run --config configs/motorway.yaml --save-video out.mp4

# count people through a doorway with your webcam, no config file
trafficlens run --source 0 --classes person --gate "door,0.5,0.05,0.5,0.95"

# the web control room
trafficlens serve
