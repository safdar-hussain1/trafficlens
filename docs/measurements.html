How a crossing is decided

A gate is a directed line segment, not a line. Every frame, each tracked vehicle's anchor moves from one point to the next; if that step's path meets the segment, the vehicle is counted once and never again.

Counting accuracy

Every crossing scored one by one against a hand-labelled set, and the gate rule measured against the two shortcuts it replaces.

What happens when the input gets worse

The same stream degraded four ways — decimated, dropped, starved of detections and jittered — with every method re-scored at every level.

What identities cost at the gate

Crossing accuracy can hide an identity problem: a split track still produces one count. This scores the identities themselves, around the gate, with the counting rule held fixed.

Speed, in two tiers

Against a synthetic scene the truth is exact and the answer is a number. Against the real motorway clip the answer is that no absolute speed can honestly be published at all.

What this does badly

Nine findings that went against what the project expected. Anyone can publish the number that came out well, and a reader has no way to tell which numbers were not published.

The engine's own tracker does not pay for itself on this clip

On clean footage it scores below both simpler baselines — by one event, so read that one as a tie — and lowest of the three at every degraded level where they differ.

It stops counting entirely at a low frame rate, and mild box jitter costs it real accuracy

At two frames a second it makes no predictions at all. Per-corner jitter of two pixels costs it many times the one-event resolution.

The one degradation it handles gracefully has an undiagnosed cause

The association-floor ablation explains its other collapses and explicitly does not explain this one. It is undiagnosed.

Nothing measures the shipped association floor as better than SORT's, except under detection dropout

Loosening the floor recovers a large amount of accuracy the moment the input degrades, and nothing at all on undegraded footage, where the two tie exactly.

Quantising the detector was measured and refused

A real saving on download and a real loss of detections. In a counting product a missed detection is a missed count, so the page pays the full weight.

The band rule fails on crossing time, not crossing count

Its totals look almost right and it lands hardly any of them on the frame the crossing happened. The per-frame rule fails the other way and over-counts wildly.

Every accuracy figure here is an upper bound

One clip, one gate, and that gate was chosen for label reliability — the easiest case for association as well as for labelling.

The flagship clip cannot be given a speed at all

A scale uncertainty this wide is not a speed figure, so the engine returns nothing and the config ships with no calibration block.

How it is built

One core, written twice. The Python engine is where the measurement happens; the TypeScript engine is what runs in this tab. Committed fixtures written by the Python engine are replayed through the browser engine in your own browser at ?selftest=1.
